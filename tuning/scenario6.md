# 데이터 양에 따른 인덱스 효율 한계 1

product 테이블에서 "상품"으로 시작하는 데이터를 찾는 쿼리를 작성하고 실행 계획을 확인한다.
단, product 테이블에는 10000개의 행이있고 모두 "상품"이라는 단어로 시작한다.

인덱스: `create index idx_product_name on product(name);`

## `select * from product where name like '상품%'`

```
-----------------------------------------------------------------------------------------------------------
 Seq Scan on product  (cost=0.00..209.00 rows=9999 width=37) (actual time=0.018..1.700 rows=10000 loops=1)
   Filter: ((name)::text ~~ '상품%'::text)
 Planning Time: 0.489 ms
 Execution Time: 2.212 ms
(4 rows)
```

## 정리
모든 product의 이름이 "상품"으로 시작하기 때문에 옵티마이저는 인덱스로 탐색하는 것 대신 Seq Scan을 선택했다.
이를 통해 알 수 있는 점은 인덱스는 적은 양의 데이터 탐색에 유리하여 많은 양의 데이터를 탐색하는데는 Seq Scan이 더 효율적일 수도 있다는 것이다.

1. 랜덤 I/O의 비용이 적지 않다는 점
2. 인덱스는 적은 양의 데이터 탐색에서 효율적

시나리오 7번에서는 인덱스를 사용할 수 있으려면 어느정도로 적은 양의 데이터이어야 하는지 확인해보겠다.
